## 一、项目目标

为西门子 S120 变频器工业手册（参数章节约 2000 页）建立 RAG 知识库问答系统，
使运维人员能就手册内容提问，并且**答案可追溯到原文**。

「可追溯」是这个项目的核心诉求，不是附加功能。

## 二、为什么从 open-webui 换到 WeKnora

原方案基于 open-webui。放弃它的直接原因是**输出结果的文档引用做得不好**，
无法满足可追溯的要求。

2026-09-09 决定改用 WeKnora（团队 fork：`OrangeSunrise/WeKnora`，上游 `Tencent/WeKnora`，v0.8.0）。

选型时确认过的两个事实，避免后续重复评估：

1. **WeKnora 是成熟产品而非脚手架**：1984 个 Go 文件、876 个测试、仅 1 处非测试 TODO。
   最初以为「自带的都是开始示例」，实际只有配置层需要补齐，代码本体不需要改。
   本次交付确实一行业务代码都没改，只改了 4 个配置文件。
2. **混合检索已内建**：团队工作汇报里设计的向量 + BM25 + RRF 融合、1024 维方案，
   WeKnora 已经实现，无需自研或迁移。汇报中规划的自研栈（FastAPI + React + Milvus）作废。

## 三、必须知情的一个落差

**WeKnora 并未真正解决最初的动机。** 它的引用只到分块级：全链路没有页码，
前端也没有 PDF 渲染器，点击引用只能看到分块原文，不能定位到手册的具体页、不能高亮。

对 2000 页的手册而言，这个差距是实质性的。本次已知情并决定**不做页级引用改造**，
即该能力暂时作废。后续若要重新纳入范围，需要跨数据层、检索层、前端三层改造，
不是配置能解决的。

讨论检索质量或引用体验时，请先确认页级引用是否已被重新纳入范围，
不要假设「换了 WeKnora 引用问题就解决了」。

## 四、本次交付范围

采取「最小可用」路径：不以 2000 页手册作为初期开发条件，先用小语料把链路跑通。

| 项 | 内容 |
|---|---|
| 部署形态 | Lite 单二进制，原生 Windows，无 Docker / WSL2 / Redis |
| 存储与检索 | SQLite + sqlite-vec（`vec0` 虚拟表）+ FTS5 bigram 分词 |
| 模型 | 本机 Ollama：`qwen2.5:7b-instruct` 生成，`bge-m3` 嵌入（1024 维） |
| 语料 | 中文维基工业类条目，清洗后全量 35MB，实际入库 300 篇 |
| 验证 | 21 条用例覆盖单文档检索、跨文档归纳、因果诊断、数值读取、拒答、引用交互、幻觉检查 |
| 代码改动 | 无。仅 4 个配置文件：`builtin_agents.yaml`、`config.yaml`、`system_prompt.yaml`、`go.sum` |

明确**不在本次范围内**的：PDF 手册解析（Lite 形态不支持）、页级引用与高亮、
重排序模型接入、S120 参数表结构化解析、参数编号元数据。

## 五、当前状态

**问答与引用链路可用。** 21 条用例 20 通过 1 失败，检索与引用的数据通路完整：
19 个去重引用全部能取到真实原文，引用浮层在浏览器中正常展开并显示对应分块。
语义检索确认生效——提问与文档标题无字面重叠时仍能正确召回。

**一个尚未解决的严重问题**：多轮追问下拒答能力失效，模型会编造语料中不存在的事实，
并为其附上引用。稳定复现 2/2。带引用的编造比纯编造更危险，因为看起来有据可查。
这条直接影响可信度，建议作为下一步的首要事项。详见 `问题与解决.md` 第 4.5 节。

三个次级偏差：引用标记逐次随机波动（14 条回答中 4 条未产出引用）、
内部句柄偶发泄漏、具体数值偶发漏读。均在 `测试记录.md` 与 `问题与解决.md` 中记录。

## 六、过程中最值钱的三条经验

这三条与具体报错无关而与机制有关，是本次耗时最多的地方，接手前建议先读
`问题与解决.md` 第一章：

1. **改 YAML 对已落库的内置智能体完全无效。** 提示词在首次启动时就被实体化写入
   `custom_agents` 表，此后数据库行是唯一权威来源。团队此前为修图片幻觉改的模板
   从未生效，直到本次排查才发现。
2. **单机部署必须压低后台模型并发。** Ollama 默认只处理一个请求，而 WeKnora 后台
   默认并发 32，导入期间会堆出约 35 个请求的队列，一次问答要等 11 分钟。
   最初判断为「服务卡死」，实际是排队。
3. **PowerShell 读 UTF-8 无 BOM 文件会静默丢行。** 112 行只读到 90 行，
   丢掉的正好是 Ollama 地址与 SSRF 白名单，而且不报错。

## 七、后续建议的优先顺序

1. **修复多轮追问的拒答失效**，这是可信度底线。
2. **收窄监听地址**到 `127.0.0.1`（当前为 `0.0.0.0:8080`，同网段可访问）。
3. **确认 PDF 解析路径**：Lite 形态不支持 PDF，而目标语料是 PDF 手册。
   需确认 docreader 服务能否在本形态下单独启用，这是通向真实目标的必经一步。
4. **接入重排序模型**，替代目前靠压低 `embedding_top_k` 抑制噪声的做法。
5. 若可追溯性要求提高，重新评估**页级引用**的改造成本。
