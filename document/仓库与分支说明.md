# 仓库与分支说明

> 用途：说明本地仓库对接的三个远端、两个发布目标各自的内容边界，
> 以及后续如何把新工作同步到远端。
> 适用对象：接手本项目的人员，以及需要在本机继续开发的原作者。

---

## 一、远端构成

本地仓库位于 `D:/D_Code/WeKnora`，配置了三个远端。执行 `git remote -v` 可核对。

| 远端名 | 地址 | 用途 |
| --- | --- | --- |
| `origin` | `https://github.com/OrangeSunrise/WeKnora.git` | 团队 fork，交付目标。同事在此 review |
| `personal` | `https://github.com/LightlyFloat/RAG-SGAI-WeKnora.git` | 个人存档，保留完整工作过程 |
| `upstream` | `https://github.com/Tencent/WeKnora.git` | WeKnora 上游，只读，用于跟踪官方更新 |

## 二、分支构成与内容边界

| 分支 | 对应远端分支 | 内容 |
| --- | --- | --- |
| `main` | `origin/main` | 团队 fork 的基线，不在其上开发 |
| `dev-qingyang` | `origin/dev-qingyang` | **交付分支**，仅含交付内容 |
| `personal-main` | `personal/main` | **存档分支**，交付内容加 AI 协作记录 |

两个发布目标的边界是本项目的一条硬约定：

- `dev-qingyang` 只含面向交付的内容，即配置改动、`document/` 下的说明文档、
  `delivery/` 下的导入脚本与语料、`source/wiki-kb/` 下的语料构建脚本链。
  该分支**不含**任何个人工作记录，也**不发起**合并请求，同事按需自行取用。
- `personal-main` 是 `dev-qingyang` 加一个归档提交，新增 `ai-collab/` 目录，
  存放 Trellis 任务产物与 Claude Code 会话记录。归档构成见该目录下的 `README.md`，
  该目录仅存在于存档分支，在交付分支上查看不到。

两个分支的全部差异即为 `ai-collab/` 目录。可用以下命令随时验证边界未被破坏：

```powershell
# 交付分支不应含 ai-collab，以下命令应无输出
git ls-tree -r --name-only origin/dev-qingyang | Select-String 'ai-collab'

# 两分支差异应全部落在 ai-collab/ 下
git diff --name-only dev-qingyang..personal-main
```

在 `dev-qingyang` 上不要创建 `ai-collab/` 目录。切换到该分支时 git 会自动移除
该目录，属正常行为，内容仍保存在 `personal-main` 分支上。

## 三、日常同步流程

### 3.1 在交付分支上开发并推送

```powershell
cd D:\D_Code\WeKnora
git checkout dev-qingyang
# 修改文件后
git add <改动的文件>
git commit -m "<类型>(<范围>): <说明>"
git push origin dev-qingyang
```

提交前建议执行 `git status --short` 逐条确认待提交内容，避免误提交本地测试文件。

### 3.2 把交付内容同步到存档分支

交付分支每次推送后，把新提交并入存档分支，使个人仓库保持最新：

```powershell
git checkout personal-main
git merge dev-qingyang
git push personal personal-main:main
git checkout dev-qingyang
```

若同期 Trellis 任务产物或 Claude 会话记录有更新，在 `merge` 之后、`push` 之前
重新复制一次归档内容：

```powershell
Copy-Item 'D:\D_Code\open-webui\.trellis\tasks\*' 'D:\D_Code\WeKnora\ai-collab\trellis\tasks\' -Recurse -Force
Copy-Item 'D:\D_Code\open-webui\.trellis\spec\*'  'D:\D_Code\WeKnora\ai-collab\trellis\spec\'  -Recurse -Force
Copy-Item "$env:USERPROFILE\.claude\projects\D--D-Code-open-webui\*" 'D:\D_Code\WeKnora\ai-collab\claude\' -Recurse -Force
git add ai-collab
git commit -m "chore(archive): 更新 AI 协作记录"
```

### 3.3 跟踪上游更新

```powershell
git fetch upstream
git log --oneline HEAD..upstream/main    # 查看上游新增提交
```

如需把上游更新并入交付分支，使用 `git merge upstream/main` 而非
`git rebase upstream/main`。合并会新增一个提交且不改写既有历史，因此无需强制
推送；变基会改写历史，对已推送到共享仓库的分支需要强制推送，风险更高。
更新 `origin/main` 本身属于仓库所有者的职责，不由本地推送。

## 五、已知前提

- 对 `origin` 的推送需要 OrangeSunrise/WeKnora 的 Write 协作者权限。
  2026-09-11 首次推送前该权限为只读，`git push` 返回 HTTP 403，
  由仓库所有者授权后方推送成功。若日后再次出现 403，先执行
  `gh api repos/OrangeSunrise/WeKnora --jq '.permissions'` 确认 `push` 是否为
  `true`。
- `personal` 指向的仓库为 Public 可见性，且 `ai-collab/` 下的会话记录未做脱敏。
  任何新部署都必须自行生成 `SYSTEM_AES_KEY`、`TENANT_AES_KEY` 与 `JWT_SECRET`，
  不得沿用记录中出现的任何值。
- 交付分支基于 `origin/main` 的 `1e36e071`，即 WeKnora v0.8.0 基线。
  未改动任何业务代码，改动范围见 `document/工作说明.md`。
