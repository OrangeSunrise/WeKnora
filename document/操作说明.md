## 一、前置与目录约定

| 项 | 值 |
|---|---|
| 仓库根目录 | `D:\D_Code\WeKnora`（示例，可任意） |
| 部署形态 | Lite 单二进制，SQLite + sqlite-vec + FTS5，无 Docker、无 WSL2、无 Redis |
| 模型后端 | 本机 Ollama，生成模型 `qwen2.5:7b-instruct`，嵌入模型 `bge-m3`（1024 维） |
| 配置文件 | `.env.lite`（不入库，从 `.env.lite.example` 复制） |
| 交付语料 | `delivery/kb-corpus/`，含已导入的 300 篇与 `manifest.csv` |
| 语料构建链 | `source/wiki-kb/scripts/`，01→07 编号即执行顺序 |

仓库中**不含**以下两个文件，需要时自行构建或索取：
`WeKnora-lite.exe`（208MB，自行构建）、`source/wiki-kb-results.tar.gz`（420MB，另行传输）。

## 二、构建

一次性准备：scoop 安装 `go` 与 `mingw`；准备 `sqlite3.h` 到 `.build/include`；
下载 DuckDB v1.5.2 到 `.build/duckdb` 并把 `duckdb.lib` 复制为 `libduckdb.dll.a`。
三步的原因见部署说明第五章，缺任一步都编译不过。

```bash
export CGO_ENABLED=1
export CGO_CFLAGS="-I$(pwd)/.build/include"
export CGO_LDFLAGS="-L$(pwd)/.build/duckdb -lduckdb -static-libstdc++ -static-libgcc"

go build \
  -tags "sqlite_fts5 duckdb_use_lib" \
  -ldflags "-s -w -X github.com/Tencent/WeKnora/internal/handler.Edition=lite" \
  -o WeKnora-lite.exe ./cmd/server
```

`-X ...Edition=lite` 不可省略，否则前端静态资源不挂载、页面请求返回 401，
免密登录接口也不生效。

前端单独用 Node 22 构建，产物拷入 `web/`（该目录不入库）：

```bash
NODE22="$HOME/.fnm/node-versions/v22.x.x/installation"
cd frontend
"$NODE22/node.exe" "$NODE22/node_modules/npm/bin/npm-cli.js" ci
"$NODE22/node.exe" "$NODE22/node_modules/npm/bin/npm-cli.js" run build
cd .. && cp -r frontend/dist/* web/
```

不要用 `fnm exec --using=22 npm ci`，Windows 上会报 `Can't spawn program`。

## 三、配置

```bash
cp .env.lite.example .env.lite
```

首次启动前必须做两件事：

1. 替换 `JWT_SECRET` 与 `SYSTEM_AES_KEY` 为随机值。**顺序至关重要**：
   `SYSTEM_AES_KEY` 用于加密模型凭据，若先以默认值启动并录入过模型配置，之后更换
   将导致已加密数据无法解密，只能清库重来。该密钥丢失同样不可恢复，须备份到团队约定位置。
2. 确认 `SSRF_WHITELIST_EXTRA=127.0.0.1` 存在，否则模型初始化会因回环地址被拦截而失败。

`.env.lite.example` 已包含本部署实测补齐的四项（SSRF 白名单、后台模型并发上限、
系统管理员提权邮箱、LLM 调试开关），每项都有注释说明为什么需要它。

## 四、启动

入口不自动加载 dotenv，须先把 `.env.lite` 导入当前 shell。**窗口保持打开，关闭即停服。**

PowerShell（`-Encoding UTF8` 不可省，否则会静默丢行）：

```powershell
cd D:\D_Code\WeKnora
Get-Content -Encoding UTF8 .\.env.lite | Where-Object { $_ -match '^\s*[^#\s].*=' } | ForEach-Object { $i = $_.IndexOf('='); Set-Item -Path ("Env:" + $_.Substring(0,$i).Trim()) -Value $_.Substring($i+1).Trim() }
.\WeKnora-lite.exe
```

Git Bash：

```bash
cd /d/D_Code/WeKnora
set -a && . ./.env.lite && set +a
./WeKnora-lite.exe
```

健康检查 `curl -s http://127.0.0.1:8080/health` 返回 `{"status":"ok"}` 即成功，
启动日志应出现 429 条 gin 路由。浏览器打开 `http://127.0.0.1:8080` 自动登录，
账号为 `admin@weknora.local`，无需密码。

## 五、模型接入

```bash
ollama pull qwen2.5:7b-instruct
ollama pull bge-m3
```

嵌入模型**必须是 1024 维**，与向量表 `vec_embeddings_1024` 的约定一致；维度一旦不匹配需重建
索引并重导全部文档，所以务必在导入任何文档之前确认。

生成模型不要用 `qwen3:4b`：它不遵守「直接输出总结正文」的要求，会把推理过程写进文档摘要，
而摘要会参与检索，进而污染问答结果。

创建模型记录**不要**用 `/initialization/initialize`（该接口创建的记录 `tenant_id` 为 0，
对当前租户不可见）。正确做法两步：`POST /api/v1/models` 创建，
再 `PUT /initialization/config/{kbId}` 绑定到知识库。

## 六、知识库的导入与替换

### 6.1 导入

界面上传适合少量文档。批量导入用交付脚本，它已处理中文文件名的编码问题：

```bash
python delivery/scripts/import_kb.py --kb <知识库ID> --dir delivery/kb-corpus/imported-300 --wait
```

知识库 ID 从 `GET /api/v1/knowledge-bases` 获取。`--wait` 会轮询到全部索引完成。

**导入前务必确认 `WEKNORA_MODEL_MAX_CONCURRENCY` 已调小（单机建议 2）。**
默认 32 会把 Ollama 队列堵满，导入期间任何提问都要排队数分钟，
这正是最初「提问长时间无回复」的原因。

不要自己拼 curl 传中文文件名：Windows 命令行按 ANSI 代码页传 argv，
会被 `ValidateInput` 拒为「文件名包含非法字符」。脚本通过 multipart 的 `fileName`
表单字段以显式 UTF-8 传递，handler 会用它覆盖 header 中的文件名。

### 6.2 确认导入完成

三个字段都要看：

| 字段 | 期望值 | 含义 |
|---|---|---|
| `parse_status` | `completed` | 解析与分块完成 |
| `summary_status` | `completed` | 摘要生成完成 |
| `enable_status` | `enabled` | 参与检索 |

批量导入期间 `summary_status` 短暂出现 `failed` 属可重试中间状态，会自行转 `completed`。
判定全部完成的唯一标准：

```sql
select count(*) from knowledges where summary_status != 'completed';  -- 应为 0
```

界面上也可看：提权为系统管理员后访问 `/platform/settings?section=runtime-queues`
查看后台队列积压。**索引未完成前不要做功能测试**，结论不可信。

导入过程中**不可重启服务**：启动时 `internal/container/reset_pending_tasks.go`
会把处于等待状态的任务标记为失败。

### 6.3 替换语料

1. 停止对外使用，确认没有正在进行的导入。
2. 删除旧文档：界面上按文档删除，或 `DELETE /api/v1/knowledge/{id}` 逐个删除。
   若要整体重来，更干净的做法是新建一个知识库并把会话指向它，旧库留作回退。
3. 若**嵌入模型或其维度发生变化**，必须重建知识库，不能只替换文档——
   向量表按维度分表，混入不同维度的向量会导致检索结果不可解释。
4. 导入新语料，按 6.1 与 6.2 执行。
5. 新建会话验证。已有会话会沿用创建时的配置快照，不会反映新配置。

### 6.4 从原始维基语料重新生成

`source/wiki-kb/scripts/` 按编号顺序执行：01 下载、02 过滤、03 质量检查、04 分块、
05 嵌入、06 向量库导入、07 评测。清洗后的全量语料为
`source/wiki-kb/data/filtered/industrial_wiki_clean.jsonl`（35MB）。
`config/categories.json` 与 `config/keywords.json` 控制抽取的概念覆盖范围，
调整它们即可改变语料主题分布。

注意 06 是往 qdrant 导入，属早期方案遗留；当前部署的向量检索由 WeKnora 内置的
sqlite-vec 承担，不需要执行 06。

## 七、调整智能体与检索参数

**改 YAML 无效。** 内置智能体的配置在首次启动时就落库到 `custom_agents` 表并把提示词
实体化，此后该行是唯一权威来源。必须走接口或界面：

```
PUT /api/v1/agents/builtin-quick-answer     # 需系统管理员
```
或界面「智能体」页。改完立即生效、无需重启，但**必须新建会话**才能看到效果。

本部署对 `builtin-quick-answer` 做了三处调整，同事复现时需一并施加：

| 项 | 由 | 改为 | 原因 |
|---|---|---|---|
| `context_template_id` | `default_context` | `detailed_context` | 前者把用户问题标注为「非指令」，导致答非所问且输出英文 |
| `embedding_top_k` | 10 | 5 | 未启用重排序时 top-10 噪声过大，模型会误称语料中没有答案 |
| `system_prompt` | 含「答案必须至少含一张图片」 | 移除全部图片规则 | 纯文本语料下该要求逼模型编造图片地址 |

若后续导入带图文档，需把图片规则加回，否则图片永远不会出现在答案里。

## 八、日志与排障入口

| 需求 | 位置 |
|---|---|
| 服务端日志 | `.env.lite` 的 `LOG_PATH` 指定的文件（默认只写 stdout，窗口关掉就没了） |
| 完整 LLM 提示词与响应 | 设 `LLM_DEBUG_LOG=true` 重启，dump 到 `LOG_PATH` 同级的 `llm_debug/`。排查语言、答非所问、引用缺失极其有效；平时保持 false，dump 含检索到的全部原文 |
| Ollama 侧排队情况 | `%LOCALAPPDATA%\Ollama\server.log`，看 `[GIN]` 行的 `/api/chat` 耗时；耗时数分钟即为排队 |
| 后台队列积压 | 界面 `/platform/settings?section=runtime-queues` |

## 九、安全收口

以下两项在交付时尚未处理，建议接手后立即执行：

1. `config/config.yaml` 第 3 至 4 行的监听地址为 `0.0.0.0:8080`。若仅本机使用，
   改为 `127.0.0.1` 以缩小暴露面。当前配置下同网段任何人都能访问该服务。
2. `SYSTEM_AES_KEY` 的备份位置需在交付记录中登记（登记位置，不登记密钥本身）。
